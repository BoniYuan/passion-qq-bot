# Passion API 常见问题补充

## 1. IP 原因

如果报错中明确提到 IP、地区限制、访问被拒绝或风控，通常是当前网络出口 IP 不稳定、多人共用、所在地区受限，或短时间内请求过多导致风控。建议先更换稳定的网络后重试，关闭频繁切换节点的代理，并降低请求频率。如果仍然失败，请提供完整错误信息、使用的模型和大致发生时间，不要发送完整 API Key。

不要仅根据“请求失败”就判定为 IP 问题。401 通常优先检查 Key，429 优先检查频率和并发，连接超时再检查网络和代理。

## 2. Temperature 和 Top P 参数

`temperature` 控制回答的随机性：数值越低越稳定，数值越高越发散。`top_p` 控制候选词范围：数值越低，输出越保守。

建议不要同时大幅调整两个参数。日常问答或代码可使用 `temperature 0.2~0.5`，文案或创意内容可使用 `0.7~1.0`；`top_p` 保持默认值即可。如果客户端不允许留空，可先使用 `temperature 0.7` 和 `top_p 1`。不同模型支持的范围可能不同，出现 400 时应先删除自定义参数并使用默认值重试。

## 3. 哈基米破甲空回

“空回”通常表示请求成功到达上游，但没有返回可显示的文本。常见原因包括内容被上游安全策略拦截、对话上下文异常、预填充或破甲提示词不兼容，以及客户端没有正确解析响应。

先新建对话，删除预填充、特殊破甲文本和非必要参数后重试；再用一句普通问题测试模型是否能正常返回。普通问题正常而特定提示词空回时，通常不是额度或网络问题。仍无法解决时，请提供模型名称、客户端名称和已隐藏敏感信息的响应截图。

## 4. Claude 3.7 报错 400

400 表示请求格式或参数不被当前模型接受。请先确认模型名称与站内上架名称完全一致，然后删除自定义 `temperature`、`top_p`、预填充、思考参数、工具调用等可选配置，使用最简单的文本对话重试。

如果最简请求正常，再逐项恢复参数，即可找到不兼容项。如果仍然 400，请发送完整错误文本、客户端名称、模型名称和大致时间，但要隐藏 API Key。不要在没有看到错误详情时直接认定是渠道故障。

## 5. 充值不到账

先刷新账户页面并等待 5~10 分钟，不要因为页面延迟立即重复支付。如果超过 10 分钟仍未到账，请私下联系管理员，提供注册邮箱、充值金额、支付时间和已打码的订单或支付截图，便于核对。

不要在公开群里发送完整订单号、支付账号、密码、Token 或 API Key。机器人不能仅根据一张支付截图宣布补款成功，应交由管理员核对后处理。

## 6. 缓存命中机制

缓存是否命中由实际模型和上游渠道决定，不是每次请求都会命中。一般需要请求前缀足够长，并且 System Prompt、工具定义、消息顺序和前缀内容保持一致。只要在前缀中改动了文字、参数、工具或消息顺序，都可能导致重新计算。

缓存通常只减少命中部分的输入计费或处理时间，不代表整次请求免费，输出 Token 通常仍正常计费。缓存也有有效期，超时后需要重新建立。最终是否命中应以请求记录中的缓存 Token 统计为准；如果渠道不返回该统计，机器人不应凭感觉判定已命中。

## 7. API 连接不上、请求发不出去

API 连接不上不一定是渠道故障，常见原因包括本地网络或代理异常、API URL 填写错误、API Key 无效、模型名称不一致、客户端配置选择错误，以及需要配合使用的小窗或辅助程序没有启动。

建议按以下顺序排查：

1. 确认浏览器可以正常访问站点，本地网络和代理没有断开。
2. 核对 API URL，注意协议、域名、路径和末尾格式，不要把后台页面地址当成 API 地址。
3. 重新复制 API Key，检查是否带了空格、换行或多余引号，不要把完整 Key 发到群里。
4. 确认客户端选择了正确的接口类型、模型和预设，模型名称应与站内上架名称一致。
5. 如果当前用法依赖小窗、反代程序或本地辅助工具，确认它已经启动并保持运行。
6. 使用最简单的新对话重试，暂时关闭自定义参数、插件、工具调用和特殊预设。

仍无法连接时，请提供客户端名称、模型名称、完整错误文字、API URL 的域名和路径（隐藏 Key），以及大致发生时间。连接超时通常优先检查网络、代理和 URL；401 优先检查 Key；404 优先检查 URL 路径或模型名称；400 优先检查请求参数和预设。

## 8. 500 All available accounts exhausted

`500 All available accounts exhausted` 表示当前上游没有可继续处理这次请求的可用账号。输入内容触发安全限制只是其中一种可能，也可能是上游账号临时不可用、额度或并发耗尽，或者账号、卡片触碰风控红线后被限制。

先新建对话，用一句普通且合规的内容重试，并减少并发和连续请求。如果普通内容也持续报错，可以稍后重试或切换其他可用模型；同时提供模型名称、完整错误文字和大致时间，由管理员检查渠道状态。不要在没有证据时直接认定是用户输入敏感，也不要向客户展示上游账号、卡片或渠道的内部明细。

## 9. Temperature 或 Top P 只能设置为 0.95~1

如果错误明确提示 `temperature` 或 `top_p` 的值只能在 `0.95~1` 范围内，说明当前模型或渠道不接受预设中的原参数。请进入客户端的预设界面，把报错中点名的参数调整到 `0.95~1` 范围内，建议先设为 `1` 后重新发送。

如果预设界面同时配置了 `temperature` 和 `top_p`，优先只修改错误中明确提到的项目；仍然报错时，再把两项都设为 `1`。这类报错是参数范围不兼容，不应优先归因于网络、余额或 API Key。

## 10. 提示不支持以模型角色结尾

如果提示“不支持以模型结尾”、`model role`、`assistant role` 或类似错误，通常是当前预设的最后一条消息角色设置不兼容。请进入预设界面，找到最后一条预设消息，把角色从模型或助手改成 `user（用户）`，保存后新建对话再试。

如果修改后仍然报错，请检查预设末尾是否还有空白的模型消息、预填充或助手消息，并暂时删除这些内容。这个问题属于消息角色和预设格式错误，不应优先归因于 IP、额度或渠道故障。

## 11. 收费计算说明

本站采用“充值比例 × 分组倍率”的方式进行价格折算。

计算公式：

每海棠 1 刀对应的人民币成本 = 充值比例 × 分组倍率。

当前充值比例根据不同充值档位可能为 `0.20`、`0.18` 或 `0.16`。分组倍率由模型、渠道或分组决定，不同模型、渠道或分组可能对应不同倍率。最终消耗以系统后台实际扣费记录为准。

例如：充值比例为 `0.16`，分组倍率为 `1.5` 时：

`0.16 × 1.5 = 0.24 元/刀`。

简单理解：充值比例越低，综合使用成本越低；分组倍率越高，对应模型或渠道的成本越高。这里的“刀”为平台内部模型计费单位，用于计算接口调用消耗，不代表可提现美元，也不等同于用户实际支付的人民币金额。
